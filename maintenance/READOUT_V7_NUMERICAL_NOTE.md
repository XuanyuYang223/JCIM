## One unused auxiliary-head tie in the CPU audit

[READOUT_V7_AUDIT.json](READOUT_V7_AUDIT.json) is **FAIL** on one exact argmax
comparison. All other frozen checks pass, including all ridge refits, all motif
predictions, all trained-task predictions, all metrics and factorial contrasts,
source isolation, frozen encoders, and the 24 historical continuity anchors.

The discrepancy is `fit_0168`: original-trained encoder, Experience A, seed 2,
full512, raw, family-only fitting. The distance head is unused by this objective
and remains exactly at its random initialization. The affected molecule is
source-training index 2596, ID `d8d5c5c84a7cc842f3ba`, not a held-out test identity.
The competing classes are 2 and 9:

| Execution | Class-2 logit | Class-9 logit | Argmax |
| --- | --- | --- | --- |
| Independent CPU | 0.6251874566078186 | 0.6251874566078186 | 2 |
| Archived CUDA | 0.625187337398529 | 0.6251875162124634 | 9 |

The maximum logit difference for that row is `1.7881393432617188e-7`. The CPU
tie selects the first class index, whereas the archived CUDA outputs have a
small strict difference. No primary motif decision, trained-task decision, or
held-out decision changes. This explains the discrepancy without changing the
saved logits, class predictions, exact-comparison requirement, or tolerance.

[READOUT_V7_NUMERICAL_CHECK.json](READOUT_V7_NUMERICAL_CHECK.json), generated by
[check_readout_v7_numerics.py](check_readout_v7_numerics.py), recomputes every
saved MLP head on both devices. Across 432 head arrays and 1,984,608 class
decisions, CPU reproduction has precisely this one discrepancy and zero motif
or trained-task discrepancies. Independent CUDA evaluation is bit-exact for all
432 complete logit arrays, with zero class discrepancies and maximum absolute
logit difference zero. This is a post-run numerical reconciliation, not a
replacement outcome for the original CPU audit.

## Full frozen audit with the recorded head-evaluation device

[audit_readout_v7_runtime.py](audit_readout_v7_runtime.py) imports the committed,
unchanged auditor and overrides only `independent_head_logits`, transferring its
saved parameters and transformed inputs to the original CUDA device. The same
fixed 128-example inference shape, two linear operations, ReLU, and output
ordering remain. Encoder reconstruction and first-gradient checks remain on CPU;
all identity, scaler, ridge, metric, seed-summary, clipping, and continuity checks
remain unchanged. Class comparisons still require exact agreement. No tolerance
is relaxed.

The first wrapper launch is preserved in
[READOUT_V7_RUNTIME_AUDIT.json](READOUT_V7_RUNTIME_AUDIT.json) as **FAIL**. CUDA
head comparisons pass, but exact ridge reproduction fails: the wrapper had
imported NumPy before the frozen auditor's environment defaults could configure
BLAS. This changed numerical execution of the independent linear solves.

The unchanged wrapper is then launched with the required environment set before
Python and NumPy initialization. The full result in
[READOUT_V7_RUNTIME_SINGLE_THREAD_AUDIT.json](READOUT_V7_RUNTIME_SINGLE_THREAD_AUDIT.json)
is **PASS**: 15 frozen encoders, 216 fits, 72 exact ridge refits, 2,016 metric
rows, 190,080 clipping records, 24 exact continuity anchors, and all paired
statistics pass; CUDA head predictions have zero discrepancies. Both wrapper
runs have the same SHA-256:

`2edfc22c0d771762d3065858eff38d7e7211bbdc6a5af43f33e42be357807fe0`.

The pre-run committed and executed base auditor has SHA-256:

`da89e3f863d65eb82b3e1c6e9c3105cafefb41b598a93084b7fcbb659dbddeff`.

The runtime wrapper verifies these provenance relationships. The base auditor,
protocol, experiment implementation, completed record, and original audit remain
unchanged. The new runtime wrapper and numerical checker are explicitly post-run
maintenance artifacts.

For a fresh matched-runtime audit, use a new output filename:

```powershell
$env:OPENBLAS_NUM_THREADS = '1'

.\.venv\Scripts\python.exe maintenance/audit_readout_v7_runtime.py --output maintenance/READOUT_V7_RUNTIME_RECHECK.json
```
